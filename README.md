# To do list — 메일로 보는 내 할 일 (웹페이지)

과거에 받은 메일(`.eml`)과 **Word(`.docx`)·Excel(`.xlsx`) 문서**를 브라우저에 끌어다 놓으면 사내 LLM 이 읽고 두 가지 탭으로 보여주는 웹페이지입니다.

## Word · Excel 문서

| 형식 | 읽는 내용 | 날짜(작년 이맘때·기한 기준에 사용) |
|---|---|---|
| `.docx` · `.docm` (Word) | 문단 + 표(행마다 `칸 \| 칸`), 회사 양식의 내용 컨트롤 안쪽 글자까지 | 문서 속성의 수정일 → 없으면 파일 수정 시각 → 압축 항목 시각 |
| `.xlsx` · `.xlsm` (Excel) | 보이는 시트의 표 (시트당 최대 300행), 날짜 서식 칸은 `YYYY-MM-DD` 로 | 같음 |

- 회의록의 액션 아이템, 일정표·업무 분장표에서 **내가 담당자인 일**과 마감을 할 일로 뽑습니다 (담당자가 다른 사람인 행은 제외).
- 문서는 '기한 기준' 범위(기본 4주)와 상관없이 항상 분석합니다 (오래전에 만든 연간 일정표의 이번 주 마감도 보이도록). 단, 8주보다 오래된 문서의 '기한 미정' 일은 숨깁니다.
- 화면에서는 문서에 **W**(Word) / **X**(Excel) 표시가 붙고, 누르면 문서 내용(작성자·수정일 포함)을 보여줍니다.
- 한글(`.hwp`)은 읽지 못합니다 → 한글에서 .docx 로 저장해 올려 주세요. Word·Excel 이 열려 있을 때 생기는 `~$` 임시 파일은 자동으로 무시합니다.
- 옛 형식 `.doc` / `.xls` 는 읽지 못합니다 → Word·Excel 에서 **다른 이름으로 저장 → .docx / .xlsx** 로 바꿔 올려 주세요.
- 암호가 걸린 파일, 손상된 파일은 '읽기 실패'로 제외됩니다. 매크로는 실행하지 않고 글자만 읽습니다.
- 추가 설치 없음 (파이썬 표준 라이브러리 `zipfile` 로 읽음).

| 탭 | 내용 |
|---|---|
| 📅 **작년 이맘때** | 지난해들(작년·재작년·그 이전, 기간 제한 없음) **같은 월·주차** 메일에서 그때 했던 일 → 올해 지난 주 / 이번 주 / 다음 주 / 이번 달 / 다음 달에 챙길 일 |
| ⏰ **기한 기준** | **이번 주·다음 주·이번 달·다음 달 할 일 요약** + 최근 메일(기본 4주)의 할 일 → **지난 주에 한 일(요약)** / 기한 지남 / 오늘 / 이번 주 / 다음 주 / 기한 미정 |

### 작년 이맘때

예) 오늘이 2026년 10월 10일(10월 2주차)이면

| 화면 | 비교하는 지난해 메일 |
|---|---|
| 지난 주 (9/28~10/4) | 2025년·2024년 **9월 5주차 · 10월 1주차** 메일 — 올해 빠뜨린 일이 없는지 확인 |
| 이번 주 (10/5~10/11) | 2025년·2024년 **10월 2주차** 메일 |
| 다음 주 (10/12~10/18) | 2025년·2024년 **10월 3주차** 메일 |
| 이번 달 (10월) | 2025년·2024년 **10월 전체** 메일 (주차별로 묶어 표시) |
| 다음 달 (11월) | 2025년·2024년 **11월 전체** 메일 (12월이면 다음 달은 1월 — 올해 1월 메일도 포함) |

- **주차**: 월요일 시작, 그 달 1일이 든 주가 1주차 (예: 2026-10-05(월)~11(일) = 10월 2주차).
  달이 바뀌는 주는 두 달의 주차를 모두 봅니다 (예: 9월 5주차 · 10월 1주차).
- 카드(지난 주 / 이번 주 / 다음 주 / 이번 달 / 다음 달)마다 LLM 요약: 지난해 그 시기에 있던 일로 올해 챙길 일을 매년 반복 / 확인 필요 / 미리 준비로 정리
- 해마다 같은 일(예: 예산안 제출)은 하나로 묶고 `2024·2025 매년` 으로 표시합니다.
- 올해 받은 메일은 이 탭의 비교 대상이 아닙니다.

### 기한 기준
- **지난 주에 한 일**: 기한이 지난 주(월~일)였던 일 + 지난 주에 받은 메일의 기한 없는 일. 메일에서 끝낸 것이 확인된 일은 `완료`(체크된 상태),
  기한이 지났는데 완료가 확인되지 않은 일은 `완료 확인 안 됨` 으로 표시합니다. 범위를 1주로 골라도 지난 주는 항상 포함합니다.
- **이번 주 할 일 요약** (탭 맨 위): 기한 지남·오늘·이번 주 기한인 일, 이번 주에 받은 메일, 그리고 '작년 이맘때' 이번 주 일을 함께 LLM 에 보내
  급한 순서로 한두 문장 + 항목(급함 / 이번 주 / 작년 참고)으로 요약합니다. `📋 복사` 가능, 메일 제목을 누르면 원문.
- **다음 주 할 일 요약**: 다음 주가 기한인 일과 '작년 이맘때' 다음 주 일을 기한 순으로 요약합니다
  (미리 준비 / 다음 주 / 작년 참고). 준비가 오래 걸리는 일은 '미리 준비' 로 표시해 이번 주부터 챙길 수 있게 합니다.
- **이번 달 할 일 요약**: 이번 달이 기한인 미완료 일(이미 지난 것 포함, 다음 주 이후 기한도 포함), 이번 달에 받은 메일의 기한 없는 일,
  '작년 이맘때' 같은 달의 일을 기한 순으로 요약합니다 (급함 / 이번 달 / 작년 참고).
  최근 메일 범위(기본 4주) 안의 메일만 보므로, 그보다 전에 받은 메일의 이번 달 마감까지 보려면 범위를 늘리세요.
- **다음 달 할 일 요약**: 다음 달이 기한인 미완료 일과 '작년 이맘때' 같은 달의 일로 다음 달을 미리 계획하게 요약합니다 (준비 / 다음 달 / 작년 참고).
- **지난 주 요약**: 지난 주 메일과 할 일을 LLM 이 주간 보고처럼 한두 문장 + 주제별 항목(완료 / 진행 중 / 확인 필요)으로 요약합니다.
  항목 옆 메일 제목을 누르면 원문이 열리고, `📋 복사` 로 주간 보고 초안처럼 붙여 넣을 수 있습니다. 요약도 저장해 두어 같은 메일이면 다시 만들지 않습니다.
- 지난 주 일은 '기한 지남'에 중복해서 나오지 않습니다. 기한 지남은 최근 8주 안의 미완료 일만 표시합니다.

요약(최대 10개)은 동시에 요청해 기다리는 시간을 줄였고, 하나가 실패해도 나머지는 그대로 보여줍니다.
두 탭에 쓰이는 메일(지난해 같은 시기 + 최근 범위)만 LLM 에 보내므로, 나머지 메일은 올려도 분석 시간이 늘지 않습니다.

- **설치 불필요**: 파이썬 표준 라이브러리만 사용 (Python 3.10 이상). 파일은 `todo_list.py`(서버·분석) + `index.html`(화면) 두 개
- **빠름**: 필요한 메일(지난해 같은 시기 + 최근 범위)만 분석, LLM 요청 4개 동시 처리, 생각(thinking) 생략 요청, 자동 알림 메일은 LLM 생략
- **다시 분석은 즉시**: 한 번 분석한 메일은 결과를 PC(`.cache/`)에 저장 → 다음에는 새 메일만 LLM 에 보냄

## LLM 서버

| 항목 | 값 | 바꾸는 곳 |
|---|---|---|
| 주소 | `http://75.12.15.121:8000/v1` (사내 vLLM, OpenAI 호환) | `todo_list.py` 맨 위 `BASE_URL` 또는 환경변수 `LLM_BASE_URL` |
| 모델 | `thinkingcap` | `MODEL` 또는 `LLM_MODEL` |
| API 키 | 필요 없음 (인증 헤더를 보내지 않음) | 필요해지면 `LLM_API_KEY` |

PC 에 사내 프록시가 설정돼 있어도 LLM 서버에는 **프록시를 거치지 않고 직접 연결**합니다 (프록시 403 방지).
화면 오른쪽 위 `LLM 연결됨 / 연결 안 됨` 표시를 누르면 연결을 다시 확인합니다.

## 실행

**VS Code**: 이 폴더를 열고 `todo_list.py` 에서 ▶ (또는 F5 → `To do list`) → 브라우저가 자동으로 열림 (`http://127.0.0.1:8780`)
**Windows**: `run.bat` 더블클릭
**터미널**: `python todo_list.py`

화면 맨 위 한 줄에서 모두 합니다: `📎 메일 (.eml)` · 내 이름 · 범위(기한 기준 탭, 기본 4주) · `분석`

1. **메일·문서 올리기**: `📎 메일·문서` 를 누르거나 그 줄에 파일(또는 폴더)을 끌어다 놓기
   - `18 / 19개` 처럼 분석 가능한 수만 표시하고, 마우스를 올리면 제외 이유(날짜 없음, 읽기 실패 등)가 보입니다.
2. **분석**: 이름을 넣고 `분석`
3. **결과**: `작년 이맘때 / 기한 기준` 으로 전환 (마지막에 본 화면을 기억)
   - 작년 이맘때: 카드(지난 주 / 이번 주 / 다음 주 / 이번 달 / 다음 달)를 누르면 요약과 목록이 바뀝니다.
   - 기한 기준: 요약 상자 위 작은 탭으로 이번 주 / 다음 주 / 이번 달 / 다음 달 / 지난 주 요약 전환. 숫자 카드를 누르면 해당 목록으로 이동, 빈 목록은 숨김
   - 할 일: 왼쪽 점 색이 우선순위(빨강 긴급 · 주황 보통 · 회색 낮음), 오른쪽에 기한, 아래에 받은 날짜와 근거 메일 — 체크하면 완료로 기억(브라우저)
   - `메일` 상자(접혀 있음)를 펼치면 분석한 메일·요약·#키워드·검색
   - 메일 제목이나 `원문` 을 누르면 **원문**(회신 인용 포함, HTML 메일은 글자로만) 표시

## 분석 안 된 파일 확인

맨 위 줄 아래 **⚠ 분석 안 된 파일 N** 을 펼치면 파일마다 이유가 보입니다.

| 표시 | 이유 | 할 일 |
|---|---|---|
| 읽기 실패 | 손상·암호 걸린 파일, 읽을 수 없는 구조 | 파일을 열어 다시 저장 / 암호 해제 |
| 옛 형식 | `.doc` · `.xls` | .docx · .xlsx 로 저장 |
| 날짜 없음 | 날짜를 알 수 없음 | — |
| 기간 밖 | 작년 같은 시기도, 최근 N주도 아님 | 범위를 늘리기 |
| 자동 알림 | no-reply·뉴스레터 등 | — |
| 분석 실패 | LLM 응답에 결과가 없거나 내용이 너무 김 (한 건씩 한 번 더 시도한 뒤 표시) | 다시 `분석` — 실패한 것은 저장하지 않으므로 다시 시도함 |
| 무시 | 임시 파일(`~$`), 한글·기타 형식 | — |

메일·문서 목록에서도 분석에 실패한 항목에 `분석 실패` 가 붙습니다.

**파일을 어떻게 읽는지 직접 확인** (서버를 켜지 않고 터미널에서):

```bash
python todo_list.py --inspect "회의록.docx" "일정표.xlsx" "메일.eml"
```

종류·날짜·상태(분석 대상 / 날짜 없음 / 자동 알림)·제목과 본문 앞부분을 보여줍니다. 본문이 비어 있으면 그 파일 구조를 알려 주세요.

## 규칙

- **기간 제한 없음**: 오래된 메일·문서도 모두 받습니다. 작년 이맘때는 지난 모든 해의 같은 시기와 비교하고(여러 해 반복된 일은 `매년`), 기한 기준 범위는 1주 ~ 5년 또는 `전체`.
  메일이 아주 많으면 처음 분석이 오래 걸릴 수 있으니 필요한 기간의 메일만 올리는 것이 빠릅니다.
- **발송 날짜를 알 수 없는 메일**은 분석하지 않습니다.
- 날짜는 `Date` 헤더(표준·ISO·한국어 형식) → 없으면 `Received` 헤더에서 찾습니다.
- 자동 알림·뉴스레터·반송 메일(no-reply, List-Unsubscribe 등)은 LLM 에 보내지 않고 목록에 `자동 알림` 으로만 표시합니다.
- 메일 묶음이 모델 길이 한도를 넘거나 응답이 잘리면 자동으로 나눠 다시 요청합니다.
- 메일 본문은 사내 LLM 서버로만 전송되며, 본문 속 지시문은 따르지 않도록 지시합니다. 결과는 원문으로 확인하세요.
- 서버는 내 PC(`127.0.0.1`)에서만 접속되며, 다른 사이트에서 오는 요청은 거부합니다. 올린 메일은 임시 폴더에 두었다가 종료 시 삭제합니다.
- 저장된 분석 결과(`.cache/`)는 화면 맨 아래 `저장된 분석 결과 지우기` 로 지울 수 있습니다.
